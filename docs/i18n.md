# i18n

Supported languages: EN, FR, IT, ES. One build per language: the UI texts are compiled in.

## Where things are

- `i18n/i18n.toml`: all UI texts, one table per key with one entry per lang (`en="..."`, `fr="..."`, multi-line `"""..."""` allowed).
- `i18n.py`: generates `src/Text.elm` for one lang (`python i18n.py gen -w -l it`), falling back to `en` for missing entries. `python i18n.py ls` prints per-lang counts.
- `Makefile` `LANGS`: the langs built/published (`public-build/<lang>`, `releases/<lang>`), each via `npm run prod -- --env lang=<lang>`.
- `public/index.js` `supportedLangs`: browser lang detection; falls back to the build's `DEFAULT_LANG`.
- `Schema.Enum.Lang`: the user lang enum (from the backend schema). `Fractale.View.lang2str` gives display names, `Utils.Date` the time-distance locale and short month names.

## Lexicon placeholders

`{{_tension_}}`, `{{_Mandate_}}`, `{{_void_}}`, ... are substituted at runtime by the org lexicon
(see `docs/lexicon.md`), with per-lang defaults in `DEFAULT_LEXICON` (`i18n.py`). Keep them
verbatim in translations, as well as `{}` format args, markdown, links and HTML.

## Adding a language

1. Backend: add the value to `enum Lang` in the schema, then `make gen` (regenerates `src/Schema/Enum/Lang.elm`).
2. `Fractale.View.lang2str`, `Utils.Date` (`toTimeI18n`, `toShortMonth`): the compiler flags the missing cases.
3. `public/index.js` `supportedLangs`.
4. `i18n.py` `DEFAULT_LEXICON`.
5. `Makefile` `LANGS`.
6. Translations in `i18n/i18n.toml`.
7. Assets server: `quickdoc.<lang>.json` and the `/<lang>/*.html` static pages.
